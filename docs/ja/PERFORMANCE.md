# 性能計測

更新日: 2026-09-05

## 受入目標

- 索引済み10万枚: ウィンドウ表示から最初の一覧まで500ms以内
- 未索引: 250ms以内に進捗を表示し、入力応答p95 100ms以内
- 検索: 10万枚でp95 300ms以内
- 評価DB確定: p95 100ms以内
- キャンセル受理: 1秒以内
- UI保持: 最大1,280件の軽量データ
- 既定設定の総メモリ: 1.5GB以内、長時間スクロール後に単調増加しないこと

受入目標と、カタログ単体の実測を区別します。実画像走査・UI・長時間スクロールを含む総合測定が終わるまで、10万枚対応を達成済みとは表記しません。

## データ生成

列挙・索引・壊れた画像の分離を測る軽量データは次のコマンドで1千、1万、10万件を生成できます。

```powershell
dotnet run --project tools/PhotoFastRater.BenchmarkData -- C:\PFR-Bench\100k 100000

# 合成メタデータ10万件でSQLiteカタログを測定
dotnet run --project tools/PhotoFastRater.BenchmarkData -c Release -- measure C:\PFR-Bench\catalog-100k 100000
```

生成物は1フォルダ1,000件の100シャードに分けます。ファイルは意図的に空であるため、実画像デコード性能の測定には使いません。JPEG/RAW混在測定には、権利上利用可能な実画像セットを別途用意してください。

### 2026-09-05 カタログ単体実測

- Windows build 26200、Intel Core i9-12900K（24論理プロセッサ）、利用可能メモリ31.76GiB
- 500件単位で合成メタデータ100,000件を新規索引: 19.31秒
- 256件の初回ページ: 33.58ms
- FTS5検索20回のp95: 186.57ms
- 評価確定20回のp95: 0.51ms
- ベンチマークプロセスのピーク作業セット: 132.82MB
- 生結果: `artifacts/benchmarks/20260905-catalog-100k/catalog-result.json`

これはSQLiteカタログ層だけの測定です。ストレージ型番を取得できなかったため媒体種別は未確定で、JPEG／RAWデコード、フォルダ走査、WPF描画、サムネイル、長時間メモリは含みません。したがって総合受入の合格とは扱いません。

## 計測条件

Windows 11、ローカルSSD、JPEG/RAW混在を基準とし、CPU、RAM、ストレージ型番、画像形式比率、総容量、cold/warm cache、再帰フォルダ数を必ず併記します。初回走査時間は固定保証せず、件数、速度、経過時間、エラー数、キャンセル応答、再走査時の解析省略率を記録します。

## 実装済みの計測用不変条件

- DBページサイズは最大256件、UI保持上限は1,280件です。
- 走査Channelは既定512件、メタデータ処理は既定4並列です。
- 画像要求は優先度別に各256件、ワーカーは6です。
- ディスクキャッシュ既定上限は10GBで、1～100GBへ制限します。

これらは単体テストで境界を検証します。応答時間とプロセス総メモリは実機ベンチマークが必要なため、現時点では未達成・未検証を区別して記録します。

## 2026-10-07 UI検証での計測

合成10万件の検索を100試行へ拡張しました。修正前のp95 447msに対し、FTS候補をUNIONし日時・ID索引でページ抽出する修正後は133.79msでした。生結果は `artifacts/ui-validation/catalog-before-query-fix.json` と `catalog-after-query-fix.json` です。warm/coldを独立した総合受入として測定した結果ではありません。

生成した640×480 JPEG10,000枚のWPFスクロールでは、軽量保持は1,280件に制限します。仮想化と画像解放の修正後の30分測定は総作業セット1.5GB以内でしたが、優先キューの待機蓄積による増加傾向を検出したため安定性は未合格としました。待機キャンセル修正後に同じ経路で再測定します。

`DispatcherP95Ms` はディスパッチャへの要求待ち時間であり、OS入力から画面表示までのp95を代替しません。`AverageRenderCallbackFps` はRenderingイベント頻度であり、物理ディスプレイのFPSではありません。全目標と実機不足は[UI検証結果](UI_TEST_REPORT.md)に記録します。

評価ボタン100試行（AutomationPeer→永続化後のモデル更新）のソフトウェア描画p95は約5ms。合成10万件では可視状態から初回Rendering callbackまで約241msでした。これらは物理入力・物理モニターの計測とは区別します。長時間メモリ増加の解消は継続検証中です。

凍結ピクセル保持後の30分: 作業セット最大860.98MB、終了時845.64MB、Dispatcher要求待ちp95 13.16ms、軽量保持最大1,280。容量上限は達成しましたが、平均増加傾向は残り、長時間安定性の合格を保留します。生結果は artifacts/ui-validation/scroll-result.json です。
