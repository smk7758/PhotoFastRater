# 性能計測

更新日: 2026-09-05

## 受入目標

- 索引済み10万枚: ウィンドウ表示から最初の一覧まで500ms以内
- 未索引: 250ms以内に進捗を表示し、入力応答p95 100ms以内
- 検索: 10万枚でp95 300ms以内
- 評価DB確定: p95 100ms以内
- キャンセル受理: 1秒以内
- UI保持: 最大1,280件の軽量データ
- 既定設定の総メモリ: 1.5GB以内、長時間スクロール後に単調増加しないこと

数値は保証済み実測値ではなく、常用ベータの合否基準です。実機測定が終わるまでREADMEで達成済みとは表記しません。

## データ生成

列挙・索引・壊れた画像の分離を測る軽量データは次のコマンドで1千、1万、10万件を生成できます。

```powershell
dotnet run --project tools/PhotoFastRater.BenchmarkData -- C:\PFR-Bench\100k 100000
```

生成物は1フォルダ1,000件の100シャードに分けます。ファイルは意図的に空であるため、実画像デコード性能の測定には使いません。JPEG/RAW混在測定には、権利上利用可能な実画像セットを別途用意してください。

## 計測条件

Windows 11、ローカルSSD、JPEG/RAW混在を基準とし、CPU、RAM、ストレージ型番、画像形式比率、総容量、cold/warm cache、再帰フォルダ数を必ず併記します。初回走査時間は固定保証せず、件数、速度、経過時間、エラー数、キャンセル応答、再走査時の解析省略率を記録します。

## 実装済みの計測用不変条件

- DBページサイズは最大256件、UI保持上限は1,280件です。
- 走査Channelは既定512件、メタデータ処理は既定4並列です。
- 画像要求は優先度別に各256件、ワーカーは6です。
- ディスクキャッシュ既定上限は10GBで、1～100GBへ制限します。

これらは単体テストで境界を検証します。応答時間とプロセス総メモリは実機ベンチマークが必要なため、現時点では未達成・未検証を区別して記録します。
