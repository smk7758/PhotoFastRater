# UI検証結果

更新: 2026-10-07。受入状態: **機械側の修正・追加検証中**。本人UAT未実施。mainへのmergeは本人の結果受領・反映後に行います。

## 完了判定

棚卸し、実検証の網羅、受入は別々です。操作台帳はXAMLの操作入口・選択肢・編集列とコードのキー・コマンド候補を抽出したものです。内部処理・同じ機能の別入口を含み、行数は成功件数ではありません。各行のNotRunは実行証拠が未対応であり、分野の統合シナリオ成功で自動的に成功へ変更しません。

現在、全入口・境界・異常系を検証済みとは判定していません。以下の実施済み証拠と、未実施・実機不足を区別します。例外の自動承認は行いません。

## 修正した問題と理由

| 問題 | 修正・波及確認 |
|---|---|
| ビューア評価が表示だけで保存されない／失敗時に表示とDBがずれる | 共通の評価サービスで直列化しDB確定後に表示・出力モデルを更新。比較と通常画面にも適用 |
| 文字入力時の写真ショートカット誤発動、Tabで写真移動 | 入力コントロールを保護しTabをフォーカス用に予約。重複キー保存を拒否 |
| 管理フォルダ・除外パターンの編集が永続化されない | 編集を保存する入口と検証を追加。保存してからスキャンする手順を明記 |
| 数値入力不正でも以前の値で出力・保存できる | WPF入力エラーを表示し送信を無効化。修正で再開 |
| 選択とバッチチェックの混同・主要ボタンの隠れ | 上部の2段操作、中央写真、右側評価、下部状態へ整理。フォルダ上部は折り返し、設定・出力はスクロール可能に |
| 暗い背景に黒文字、小さい説明、選択肢の初期値欠落 | 共通テーマの文字・境界・ボタン、12 DIP下限、型付き選択値を調整 |
| 全写真のサムネイル生成、一覧スクロールで空画像・大量メモリ | 仮想パネル、可視範囲の再読み込み、範囲外の画像解放、64枚のデコードLRU、ツリー遅延読み込み |
| 画像キューの未完了待機が蓄積 | 優先キュー選択時に負けた待機をキャンセル。30分測定を再実施中 |
| CR2・ORF・RAF・RAWの埋め込みJPEGを取得できない | サイズだけで判断せず、デコード可能な最大プレビューを探索。センサーのlossless JPEGは飛ばす |
| SNS出力の元画像上書き・同名上書きリスク | 同一元パスを拒否、一時保存から上書き禁止移動、同名連番、実出力パス通知 |
| フォルダからDBへ低い星・フラグだけの変更が転送されない | 置き換え確認と256件単位のトランザクション。再実行と値保持を回帰検証 |
| インポートしたRAW/JPEGにペアIDがない | 異なるバッチでも実際の同名RAW/JPEGをリンク。PNGを誤リンクしない回帰テスト |
| 比較の固定が二重反転し、案内したドラッグが未実装 | 固定の状態更新をコマンドへ統一し、画像ドラッグのパンを実装。保存失敗を画面内で説明 |
| 終了時の二重Dispose、同期の復旧待ちで起動が遅れる | DIの所有権に合わせて破棄し、同期復旧はウィンドウ表示後に実施 |

画面構造はUIの入口と表示に限定し、評価・画像・DB・保存I/Oのサービス境界を維持しています。再構成前後の入口はAutomation IDと[操作台帳](UI_OPERATIONS.csv)で追跡します。

## 実施済み証拠

- Release回帰テスト: 74件成功。DB、評価失敗・連打、設定分離、不正JSON、旧セッション、出力原本保護を含む。
- WPF統合: ソフトウェア描画29シナリオ成功。実際の本番DI・ウィンドウ・コントロールを使用。一部ボタンはAutomationPeerで実行、ファイル選択・確認と外部シェルは代替実装。OSのファイル選択や外部アプリの実動作を証明しない。
- ネイティブUI Automation: フォルダ起動・写真選択・星5のセッション保存、実モーダル取消、終了コード0。DPI 144、PerMonitorV2をOS APIで確認。
- RAW: CC0のCR2・CR3・NEF・ARW・DNG・ORF・RAF・RW2・RAW、9形式のサムネイルと埋め込みJPEGを実デコード。取得条件・カメラ・URL・サイズ・SHA-256は[素材台帳](../../artifacts/ui-validation/raw-manifest.json)。実撮影RAW/JPEGペアや全カメラの対応証明とは区別。
- 互換性: 既存5 migration時点のDBを再現して二度起動、評価保持、移行前バックアップ復旧、バックアップ失敗時の旧DB保持を確認。実ユーザーのDBは参照しない。旧mainの全データ形態を検証した証拠とは区別。
- 合成10万件、100試行の検索p95: 修正前447ms、修正後133.79ms。カタログ層の目標300msを満たす。UIの入力応答や実画像10万枚の受入を代替しない。
- 30分スクロール（待機処理修正前）: 10,000枚の生成実画像、軽量保持1,280件、作業セット最大約1.01GiB。ただし増加傾向が続くため長時間安定性は未合格。修正後の測定結果を追記する。

生結果は `artifacts/ui-validation` の `wpf-results-*.json`、`native-results.json`、`catalog-*-query-fix.json`、`scroll-*.json`。画像はローカルの `screenshots` 配下です。WPF RenderTargetBitmapの画像を確認しました。ロック画面の物理スクリーンショットはUI証拠に採用しません。

## 環境と未検証事項

実機: Windows 11 build 26200、.NET 10.0.12、i9-12900K、RAM31.76GiB、Samsung990 EVO Plus NVMe、Intel UHD770／driver31.0.101.5592。単一3840×2160・150%、WPF Tier2。ソフトウェア描画を強制した結果と既定描画を分けて記録します。Tierや設定だけでは各フレームがGPUで描画されたことを証明しません。

| 未完了 | 理由・残るリスク | 代替・後日の確認 |
|---|---|---|
| 指定解像度と100／150／200%の全実機表示 | 利用可能な物理表示が1種類。文字・画像欠けが残る可能性 | DIPサイズの縮小レンダリングを実施。実機で設定を変更して全ダイアログを確認 |
| 混在DPIのモニター移動・境界・最大化／復元 | 複数画面なし。移動時の位置・レイアウトは未確認 | PerMonitorV2有効を確認。100↔150、150↔200の実機で実施 |
| 物理入力、読み上げ、フォーカスの視認性 | ロック中のため実利用の操作感は測れない | RoutedEvent／AutomationPeer／UIAを区別して実行。解除後に人間が確認 |
| OSファイル選択、コピー、外部アプリ、ごみ箱 | WPF統合の代替実装はOS側の成功を証明しない | コピー素材で各ネイティブ経路・取消・失敗を確認 |
