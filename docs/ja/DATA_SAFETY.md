# データ保護

更新日: 2026-09-05

## 正本と保存順序

評価、お気に入り、リジェクト、ペア連動状態はSQLiteを作業中の正本とします。ライブラリ画面の評価操作は同一トランザクションでDBを先に確定し、その後にXMP sidecarを永続キューへ予約します。XMP書き込みに失敗してもDBの評価は取り消しません。

各写真は`同期済み`、`同期待ち`、`権限不足`、`競合`、`失敗`の状態を持ちます。アプリ終了時に未処理だった項目はDBに残り、次回起動時に再度キューへ取り込みます。

## XMP sidecar

- sidecar名は拡張子を含む元ファイル名に`.xmp`を追加します。例: `IMG_0001.CR3.xmp`。
- RatingはXMP標準の`-1`、`0`～`5`を使います。
- Favorite、Rejected、更新UTC、リビジョン、更新元はPhotoFastRater名前空間へ保存します。
- 既存XMPの未知要素・属性は保持します。
- 同じディレクトリへ一時ファイルを書き、flush後に置換します。途中失敗で既存sidecarを途中状態にしません。
- XMLのDTDと外部実体は無効にし、外部参照を読み込みません。

## JPEG埋め込みメタデータ

JPEGの星評価を埋め込む処理は、ユーザーが明示した場合に限ります。WICが既存メタデータ領域をインプレース更新できない場合は失敗として返し、画素の再圧縮は行いません。通常の評価操作は元画像へ書き込みません。

## 削除

写真ファイルの削除操作は完全削除ではなくWindowsごみ箱へ移動します。ごみ箱移動が成功するまでDB記録を残すため、OS操作に失敗して写真を一覧から見失うことはありません。DBからの登録解除は元ファイルを変更しません。

## 派生画像の書き出し

バッチ書き出しは元画像と別のファイルだけを作成し、元画像をインプレース更新しません。出力は一時ファイルが完成してから上書きなしで確定し、同名が存在する場合は連番を付けます。処理失敗やキャンセル時は未完成の一時ファイルを除去し、既に確定した出力と元画像は保持します。RAWフル現像は実装せず、未対応結果として明示します。

## DB migrationと復旧

保留中のmigrationがあり既存DBが存在する場合は、SQLiteのオンラインバックアップAPIでWALを含む一貫したコピーを`%LOCALAPPDATA%\PhotoFastRater\Backups`へ作成してからmigrationを実行します。

復旧時はアプリを終了し、現在の`photos.db`を別名で退避してから、目的のバックアップを`photos.db`へコピーします。復旧元を確認できるまで古いDBと旧セッションJSONを削除しないでください。

## 旧フォルダセッション

旧バージョンが一時ディレクトリへ保存したJSONは読み取り互換を維持します。読み込み成功時は`%LOCALAPPDATA%\PhotoFastRater\Sessions`へSHA-256ベースの名前で原子的に保存し直しますが、旧ファイルは自動削除しません。10万枚での全件JSON再保存は暫定経路であり、DBカタログへの移行後に通常操作から外します。
