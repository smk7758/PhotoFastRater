# 全UI操作検証・受入手順

対象: Windows 11 x64。作業ブランチ `feat/ui-validation-and-ux`。既存のユーザーデータは検証に使用しません。

## 判定と台帳

棚卸し、実検証、本人UATは別々に判定します。操作入口は[UI_OPERATIONS.csv](UI_OPERATIONS.csv)に登録します。
`tools/validation/Get-UiInventory.ps1`がXAML操作とコード候補を抽出します。候補の存在は成功の証拠ではありません。
台帳のNotRunは未実施、Passedは証拠付き成功、Failedは不一致、Blockedは素材/環境不足、Internalは利用者操作ではない内部処理です。
内部処理と重複は入口との対応をNotesに記録し、利用者操作を集計から隠しません。実装変更後は再抽出差分をレビューします。

Must: データ損失、互換性不良、保存失敗、主要操作不能、必須環境での表示欠け、誤操作、性能必須目標の未達。
Should: 完了可能だが発見/理解が難しい操作。Could: 好み、装飾、追加便利機能。
Must解消まで受入不可。Should延期は本人合意を記録。外部依存のBlockedは理由・リスク・後日の手順を本人へ提示し、明示的な限定受入がない限り除外しません。
固定回数上限はなく、具体的な問題と重大度で改善を継続します。

## 分野別の期待結果

| 分野 | 正常・前提・取消・境界の契約 |
|---|---|
| 起動/終了 | 通常/フォルダ/両引数順で同じプロファイル。引数不足/不明は説明付き失敗。空/複数ウィンドウ/同期中の終了でハングしない |
| インポート | サブフォルダを登録、同パス再実行で重複しない。中断でも確定済みを保持し、再実行可能。破損は個別結果、処理中も応答 |
| 一覧 | クリックとチェックは別状態。グリッド/ツリー/検索/欠損/追加ページの件数と選択が一致。256/1280前後の境界、ゼロ結果で説明あり |
| 評価 | 全入口の星0～5/F/リジェクトが再起動後も保持。DBを先に確定、同期失敗を成功と誤認させない。入力欄で誤評価しない |
| フォルダ | 開く/保存/再読込/DB追加、全種類・評価・名前・日付フィルター、リセット、先頭/終端。ペア展開と評価保存が一致 |
| 閲覧 | 独立/インライン/外部ビューアの入口、画像向き、EXIFなし、選択切替、閉じる順序。外部アプリ失敗は説明 |
| 比較 | 2/3/4枚の不足時説明、同期ON/OFF、ズーム/パン/リセット、固定/入替/次の組/評価/自動送り/終端 |
| 整理 | 空選択/空名/重複名/日本語。タグ検索、親子コレクション追加、イベント候補は確定前に保存しない。再確定で重複しない |
| 出力 | 全形式・回転・品質・寸法・命名・クロップ・枠・EXIF位置。元画像保持、同名上書きなし、中断・部分失敗・再試行 |
| 設定 | 全スライダー境界、不正/空数値、保存取消、再起動反映、書込拒否、壊れたJSON。設定ダイアログで他の表示設定を初期化しない |
| 管理 | フォルダ追加/削除/有効/再帰/スキャン、除外の有効/種類/説明/パターン、空・重複・不正入力と実スキャン結果 |
| キー | 全既定/変更/取消/初期化/重複/再起動/文字入力。Tabのフォーカス移動を写真操作が奪わない |
| データ操作 | コピー値、関連アプリ/エクスプローラーの対象、埋込の明示確認、DB解除で原本保持、ごみ箱移動失敗でDB保持 |

## データ・互換性・環境

専用領域 `artifacts/ui-validation/profiles` とコピー画像を使用。`--data-dir`指定時は設定、キャッシュ、旧セッション、一時保存も分離します。
空、1～4枚、255/256/257、1279/1280/1281、実画像1000/10000、合成10万件を用意します。
縦横/EXIFなし/長い日本語/同名/破損/欠損/読取専用/検索特殊文字/RAWペアを含みます。
RAWはCC0素材のURL・形式・カメラ・サイズ・SHA-256を保存し、元ダウンロードを変更しません。派生JPEGペアと実撮影ペアを区別します。

旧main、変更前main、各migration時点のコピーDBで写真・評価・ペア・タグ・コレクション・イベント・同期状態の保持を確認します。
旧JSON/旧一時セッション、バックアップ復旧、二度起動、不正JSON、書込拒否、バックアップ/移行失敗を検証します。

表示: 1366×768/100%、1920×1080/100・150%、3840×2160/200%、混在100↔150・150↔200%。
移動/またがる/最大化/復元/ダイアログ位置/画像/フォント/スクロールを確認。模擬サイズだけでは実DPI成功としません。
GPU/ソフトウェア描画の双方で実描画方式を記録。操作説明12 DIP以上、通常文字4.5:1/主要状態3:1を目安とし、色のみの区別を避けます。
OSビルド、CPU、RAM、媒体、GPU/ドライバー/Tier、DPIと検証commitを証拠に記録します。

性能は[PERFORMANCE.md](PERFORMANCE.md)の既存目標を採用。cold/warmを分け、入力/検索/評価各100回以上、30分スクロールのメモリを測定します。
初回一覧500ms、進捗250ms、入力p95 100ms、検索300ms、評価100ms、中断1秒、軽量保持1280件、作業セット1.5GBが目標。
FPSも測定しますが独立した固定合否値は設けません。合成10万件の成功を実画像10万枚の総合受入に置き換えません。

## 最後に行う本人UAT

機械側の検証と修正後に配布物・結果表・ガイドを渡します。結果が返るまで確認待ちで、mainへmergeしません。

1. 手順を見ずに写真を開く→評価/お気に入り/リジェクト→検索/比較→整理→クロップ出力→設定と再起動を試します。
2. 各課題の成功、迷い、誤操作、読みにくさ、説明との不一致、発見/理解/見やすさを5段階と理由で記録します。
3. [USER_GUIDE.md](USER_GUIDE.md)を読みながら台帳の全利用者入口を確認します。大量境界・エラー注入は自動証拠を別管理します。
4. Must/Should/Couldで再分類し、修正後は該当課題を再確認。4点以上は改善目標であり点数だけを無条件な合否にしません。

回答票: `操作ID / 成功・失敗 / 実際の結果 / 迷った箇所 / 評価1～5と理由 / スクリーンショット / 希望`。
本人は仕様を知っているため、手順なし操作は参考評価であり初心者の客観的証明ではありません。
将来の初利用者には同じ課題を助言なしで実施し、完了時間・迷い・誤操作・助言要求を記録します。今回は計画のみです。
